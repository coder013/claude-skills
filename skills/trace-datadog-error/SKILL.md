# trace-datadog-error

운영 에러 메시지를 받아 Datadog 로그에서 발생 패턴을 추적·요약한다. 매번 Datadog UI를 수동으로 뒤지는 시간을 압축하는 게 목적.

**전제조건**: Datadog MCP 서버가 현재 세션에 등록되어 있어야 한다 (`.mcp.json` 또는 `~/.claude/.mcp.json`). 없으면 사용자에게 알리고 중단한다.

---

## 실행 절차

### Step 1 - 입력 파싱

사용자가 준 에러 메시지·스택트레이스에서 추출한다:
- **정적 식별 문구**: 매번 동일하게 등장하는 부분 (예: `Row was updated or deleted by another transaction`, `Duplicate entry`, `for key '<table>.<index>'`)
- **동적 토큰**: 매번 달라지는 부분 — 정규화 대상
  - 숫자 시퀀스 (예: `106123939-106128402-0`)
  - UUID/해시
  - ISO 날짜·타임스탬프
  - 엔티티 ID (`#0`, `#1234`)
- **사용자가 명시한 시간 범위**: 있으면 우선 사용, 없으면 기본 7일
- **명시된 발생 시각**: 있으면 ±10분 정밀 검색에도 활용

### Step 2 - Datadog 검색 전략

**검색 우선순위 (위에서부터 시도, 결과 나오면 멈춤)**:

1. 가장 고유한 **정적 문구 + 식별자** 조합으로 정확 매칭
2. 0건이면 **정적 문구 단독**으로 범위 확장
3. 0건이면 **저장 계층 확장** (hot → flex → online archives)
4. 0건이면 **시간 범위 확장** (7일 → 30일)
5. 그래도 0건이면 0건임을 정직하게 보고하고, 유사 패턴(같은 키워드의 다른 테이블/도메인)을 함께 제시

**⚠️ Datadog 풀텍스트 토큰화 함정**:
- 점(`.`)·하이픈(`-`)은 토큰 구분자로 처리됨
- `UserCenterInfoRelET` 단독 검색 → 매칭 안 됨
- 따라서 **정적 영문 문구를 그대로 따옴표로 묶어** 검색하는 게 안정적 (`"Row was updated or deleted by another transaction"`)

**시간 변환**: Datadog 로그 타임스탬프는 UTC. 사용자 표시는 항상 **KST(+9)** 로 변환.

### Step 3 - 결과 집계

다음 항목을 정해진 순서대로 정리한다.

```markdown
## 검색 결과

### 1. 총 발생 건수
- N건의 로그 라인 (= 약 M개의 고유 에러 이벤트)
- status별 분포: error N / warn N / info N

### 2. 최초 발생 시각 (KST)
- YYYY-MM-DD HH:MM:SS.sss

### 3. 최근 발생 시각 (KST)
- YYYY-MM-DD HH:MM:SS.sss
- (그 후 추가 발생 여부 명시)

### 4. Service 분포
| service | env | cluster/region | 건수 |

### 5. 호출 경로 / 엔드포인트
- 컨트롤러/엔드포인트 식별 (`http.route`, `resource.name`, 또는 스택트레이스)
- 호출 체인 (스택트레이스 기반)
- 예외 종류

### 6. 시간대별 분포
| 분 (UTC / KST) | 이벤트 수 | 비고 |
- 스파이크 / 산발 / 종료 시점 명시

### 7. Datadog UI 링크
- 정확 매칭용 링크
- (있으면) 사용자 보고 시각 ±10분 범위 링크
```

### Step 4 - 근본 원인 가설 (보너스)

스택트레이스·로그 패턴에서 단서가 보이면 **"추가 관찰"** 섹션에 가설을 적는다. 단정하지 말고 "~으로 보입니다", "점검 필요" 톤으로.

예: 엔티티 ID가 `#0`인 점, 동시 트랜잭션 패턴, 특정 시간대 집중 발생, 동일 사용자/세션 반복 등.

### Step 5 - 결과 보고 후 추가 질문 유도

마지막에 한 줄로 마무리:
> 더 깊이 파볼 항목이나 다른 시각/필드 분포 보고 싶으시면 알려주세요.

---

## 출력 톤

- 한국어로 답변
- 표·코드블록 적극 사용해서 한눈에 보이게
- 0건이거나 불확실하면 정직하게 명시 (추측으로 채우지 말 것)
- 사용자가 준 시간이 있으면 그 시각이 결과 안에 잡혔는지 명시적으로 표시
